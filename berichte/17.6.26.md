## Daten

Daten werden im Computer binär gespeichert. Damit Texte lesbar dargestellt werden können, wurde der ASCII-Code entwickelt, bei dem die wichtigsten Zeichen in einem Byte gespeichert sind.

Da ASCII nicht genügend Platz für Sonderzeichen wie ä, ö oder ü hatte, entstanden verschiedene Codepages, die je nach Region unterschiedlich waren.

Weil dadurch viele Kompatibilitätsprobleme auftraten, wurde Unicode eingeführt. Unicode kann alle Zeichen darstellen, würde aber mit einer festen Länge von 4 Byte viel Speicher benötigen.

Deshalb wurde UTF-8 entwickelt. Dabei werden ASCII-Zeichen weiterhin platzsparend gespeichert, während andere Zeichen je nach Bedarf mehrere Bytes verwenden.

## 1. XXD

Der Befehl `xxd` sorgt dafür das eingegebene Normale Buchstaben in Asc Code angezeigt werden.

bsp:
```sh
echo "a" | xxd
00000000: 610a                                     a.
```

### Die Optionen `-n -r -p` 

`-n` bei echo verhindert den automatischen Zeilenumbruch.

`-p` bei xxd zeigt nur die Daten an, ohne zusätzliche Informationen.

Mit `-r` macht xxd die Umwandlung rückgängig und wandelt die Hex-Daten wieder in normalen Text um.

bsp mit Emojis:

```sh
echo -n "😃" | xxd -p
f09f9883
```


```sh
echo -n "f09f9883" | xxd -r -p
😃
```

## Übung (Hex Dump) 

### Aufgabe:
Finde heraus wie die Ausgabe in Binär (0 und 1) mit xxd und hexdump möglich ist.

### Lösung:
Mit der Option -b kann die Ausgabe als Binärzahlen (0 und 1) dargestellt werden. Das b steht dabei für binary dump.

bsp:
```sh
echo -n "A" | xxd -b
echo -n "A" | hexdump -b
```

### Aufgabe:
Manchmal wird der in dem Zusammenhang (vor allem in der Netzwerktechnik) der Begriff “octet” verwendet. Was ist die Bedeutung? Gibt es einen Grund diesen Begriff zu verwenden?

### Lösung: 
Ein Octet besteht genau aus 8 Bit. Der Begriff wurde früher verwendet, weil ein Byte nicht immer 8 Bit groß war. Mit `Octet` war eindeutig festgelegt, dass immer 8 Bit gemeint sind. Deshalb wird der Begriff bis heute häufig in der Netzwerktechnik, z. B. bei IP-Adressen, verwendet.

### Aufgabe:
xxd unterstützt eine Option `-E`. Was macht diese? Ist diese heutzutage noch relevant?

Lösung:
Die Option `-E` bewirkt, dass `xxd` die EBCDIC-Zeichentabelle statt ASCII verwendet. Heute ist das kaum noch relevant, da fast alle Systeme ASCII bzw. `UTF-8` nutzen. Nur auf einigen älteren Systemen kann diese Option noch nützlich sein.

Um einen dezimalen Wert (ASCII Ziffern) als Binärwert in ein File zu schreiben können folgende Befehle verwendet werden:
$ value=65534
```  
$ printf "%.8x" $value | xxd -r -p >data.bin
```
### Aufgabe:
Was macht das printf und der Ausdruck %.8x?

Wie würdest du jemanden (mit einem Bash Grundverständnis) erklären wie diese Zeile die Aufgabenstellung löst.

Finde einen Weg um den 4 Byte Binärwert aus der Datei wieder als Dezimalwert darzustellen. 

### Lösung:
`printf "%.8x"` $value wandelt den Wert in eine 8-stellige Hexzahl um. Die 8 sorgt dafür, dass fehlende Stellen mit Nullen aufgefüllt werden.

Anschließend wandelt xxd -r -p die Hexzahl in Binärdaten um und speichert sie in data.bin.

Zur Rückumwandlung in eine Dezimalzahl:

```sh
echo $((16#$(xxd -p data.bin)))
```

### Aufgabe:
Was macht die -i Option von xxd? Was könnte eine mögliche Anwendung sein?

### Lösung:
Die Option `-i` gibt den Inhalt einer Datei als C-Array aus. So können Binärdaten direkt in ein C-Programm eingebunden werden, z. B. für Bilder, Icons oder andere Dateien.
